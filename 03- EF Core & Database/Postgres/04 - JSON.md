كلنا عارفين ان الـ JSON هو نوع من أنواع الـ Text بس ب Rules محددة زي أنه بيكون **Key-Value Pairs** بيكون لي **Parser** يتعامل معاه ويفكه لأن الستراكشر بتاعه واحد عكس الـ Text بيكون عشوائي

هنتكلم عن:
1. ازاي تخزن الداتا وتختار JSON ولا JSONB وليه
2. أيه احسن شكل تخزن بيه JSON

4. الفانكشنز المختلفة وازاي توصل للبيانات جوا الـ JSON

## Storing JSON
لو عندك JSON مكتوب زي:

```json
{
  "name": "Ahmed",
  "age": 21,
  "city": "Cairo",
  "name": "Shawki"
}
```

وعايز تخزنه في Postgres بما أنها بتدعم الـ JSON، هتتوه هتلاقي كذا نوع زي `JSON` وفي كمان `JSONB` هتلاقي الكل بيقولك استخدم `JSONB` طب ليه يعني واستعمل ايه

الـ `JSON` بيخزن الداتا زي ما هي وكل ما عايز تجيب داتا هيعمل عملية **Parsing** للداتا عشان يبعتها فدي عملية بطيئة في الـ Read بس سريعة ك Write عشان مش بتتعب وهي بتحط الداتا وبما أنه بيخزن الداتا زي ما هي طبعا بعد ما يتأكد أنها JSON فهو مش بيعمل أي عملية Format يعني بيخزنها زي ما هي بالـ White Spaces بالتكرار بكله
يعني بيخزنها كدا بالضبط

```json
{
  "name": "Ahmed",
  "age": 21,
  "city": "Cairo",
  "name": "Shawki"
}
```

ولو عملت `SELECT` عادية للعمود هيرجعلك الكلام بالمسافات والتكرار زي ما هو

الـ Parser بيشتغل بس لما تستخدم Operator أو Function عشان تسحب قيمة معينة من جواه زي `data ->> 'name'` ساعتها بيمشي على النص من الأول للآخر عشان يلاقي الـ Key

وبما إنه بيلف عليهم بالترتيب فلو لقى Key مكرر بيعمل **Overwrite** في الميموري ويرجعلك آخر قيمة

المشكلة هنا إن اللفة دي بتتكرر مع كل عملية بحث في الداتا، وده اللي بيخلي الـ Read بطيء على عكس الـ Write اللي بيكون سريع لأنه بيبعت الكلام زي ما هو من غير ما ينضفه أو يرتبه.

إنما الـ `JSONB` لما بتحط الداتا بينادي الـ **Parser** ويبدأ يفك الداتا ويضبطها مرة واحدة فدي بتبقى بطيئة لما تـ **Write** الداتا لأنها بتعمل عملية تحويل، بس بعدها في الـ **Read** بتبقى سريعة جدا لانك مش كل مرة هتعمل **Parsing**

وهتخزنها بالشكل ده:

```json
{"age": 21, "city": "Cairo", "name": "Shawki"}
```

بتشيل الـ White Spaces والتكرار وبتجيب آخر قيمة

## Designing JSON Documents
تمام يعم أحنا عرفنا الـ JSON بس يعني كدا خلاص هروح استعمله وخلاص في أي حاجة، ولا في حاجات المفروض اعملها وتوصيات لازم امشي بيها عشان معكش الدنيا والداتا بيز تقلب وكأنها MongoDB والدنيا تبقى عك

الـ JSON بيديك **Flexibility** كبيرة وده مفيد جدا لو حاجة ملهاش استراكشر واضح أو بتتغير كتير زي مثلا الـ **Articles** أو مواصفات المنتجات، ومع ذلك بردو الأفضل يكون عندك **Predictable Structure** حتى لو مش مفروضة من الداتابيز

وممكن تجمع بين الـ JSON والـ Relational Model عادي في نفس الأبلكيشن على حسب البيزنس بتاعك

بس في مشكلة ممكن تحصل لو عملت **JSON Documents** كبيرة أنك لما تيجي تعدل مثلا في الـ JSON في ROW معين هيحصل حاجة اسمها **Row-Level Lock** بيقفل الـ Row عشان يعدل فيه براحته فلو الـ Document كبير هيوقف أي حاجة تانية ويحصل LOCK عشان يقعد ينفذ الطلب بتاعك

عشان كدا حاول تمشي بـ **Atomic Datum** يعني سيباريشن متحطش كل حاجة في Document وكأنك في NoSQL DB

## JSONB Indexing
لما يكون عندنا عدد كبير من الـ Records اللي بتخزن JSON Documents، البحث جواها بياخد وقت وعلشان نحسن الأداء PostgreSQL بتدعم استخدام **GIN Index** مع `jsonb`.

الـ GIN Index بيساعدنا نبحث عن Keys أو Values موجودة داخل الـ JSON بدل ما نحتاج نفحص كل Document

بوستجري بتوفر نوعين من GIN Operator Classes
**jsonb_ops**
الـ Default، وبيسمح بالبحث عن وجود Keys أو Values، ويدعم مجموعة أكبر من الـ Operators زي `?` و`@>`.
**jsonb_path_ops**
هو أقل مرونة بس بيكون أسرع وأصغر في الحجم، خصوصا `@>` بس مش بيدعم كل الـ Operators اللي بيدعمها النوع الأول.

ممكن بردو نعمل **Expression Index** على جزء معين من الـ JSON بدل ما نعمل Index على الـ Document كله، وده بيكون مفيد لو البحث دايما بيتم على Key معين.

## JSON Functions & Operators
هنا هنتكلم عن الفانكشنز المختلفة للـ JSON اللي بوستجري مقدماها وعايزين نثبت أننا دايما بنسبة 99% هنشتغل بـ `jsonb` فالكلام هنا موجه لي
### 1. jsonb Subscripting
أنت تقدر تأكسس الداتا وكأنك في لغة برمجة بالضبط عن طريق الـ `[]`
مثال بسيط زي كدا:

```sql
select jsonbkey['name'] from test
```

أنت هنا عايز تجيب ملف الـ JSON وتجيب منه ال Key اللي اسمه `name` وممكن تعمل بقى Update أو أي حاجة انت عايزها زي كدا:

```sql
update test t set jsonbkey['name'] = '"Ahmed"' where t.jsonbkey['name'] = '"Shawki"'
```

أو Delete هنا انت بتمسح الـ Row كله:

```sql
delete from test where jsonbkey['name'] = '"Ahmed"'
```
### 2. `->` , `->>`
دي زيها زي الـ Subscripting بس طريقة مختلفة
لو `->` فبتكون هترجع القيمة ك `jsonb` يعني ب `""` عشان لو عايز تكمل بحث لو في **Nested Object**

لو `->>` هنا بيرجعلك الـ **Text** صريح عشان لو هتعمل بيه حاجة هوريك مثال

لو عندك اوبجيكت كدا:

```json
{"age": 20, "name": "Ahmed", "address": {"city": "cairo", "street": 20}}
```

### 3. Containment `@>` & Existence `?`
الـ `@>` بتسأل هل الـ JSON الكبير اللي متخزن جواه JSON الصغير اللي عاليمين ولا لا

```sql
SELECT jsonbkey FROM test WHERE jsonbkey @> '{"address":{"city": "cairo"}}';
```

إنما `?` بتسأل هل الـ `Key` موجود في نفس المستوى ولا لا لو بتبحث عن Key معين

```sql
SELECT * FROM test WHERE jsonbkey ? 'age';
```
